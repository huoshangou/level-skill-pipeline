# 关卡类型 × 模块生成规则 v1.0

> 本文档定义不同关卡类型下的模块生成策略。
> **设计原则：按需生成，不浪费策划精力在无意义的模板内容上。**

---

## 类型分类

| IR.type | 类别 | 代表案例 |
|---------|------|---------|
| `POI` | **空间类** | 好莱坞艺术馆、标志性建筑探索 |
| `MainMission` (场景叙事型) | **空间类** | 主线任务关卡（有固定场景/空间） |
| `SideQuest` (探索类) | **空间类** | 支线任务（有固定 POI 关联） |
| `OpenWorldEvent` | **玩法类** | 大世界动态事件（如卡车玩法、连续破坏） |
| `OpenWorldChallenge` | **玩法类** | 大世界挑战（如区间破坏变体A） |
| `MainMission` (纯玩法型) | **玩法类** | 没有固定场景的纯机制玩法 |
| `SideQuest` (纯机制类) | **玩法类** | 纯机制支线任务 |

**判断规则：** 如果 IR.SPACE 的空间区域是"概念性状态区域"而非"实际地图场景区域"，则视为**玩法类**。

## 模块生成矩阵

| 模块 | 空间类 (POI等) | 玩法类 (OpenWorldEvent等) | 说明 |
|------|--------------|--------------------------|------|
| `level_overview` | ✅ 必生成 | ✅ 必生成 | 任何类型都需要概览 |
| `bubble_chart` | ✅ 必生成 | ✅ 必生成 | 核心流程图，模式自动切换 |
| `emotion_curve` | ✅ 必生成 | ✅ 必生成 | 情绪设计是核心 |
| `asset_list` | ✅ 必生成 | ✅ 必生成 | 资产需求任何类型都有 |
| `storyboard` | ✅ 必生成 | ✅ 必生成 | 关键帧叙事 |
| `tech_req` | ✅ 必生成 | ✅ 必生成 | 程序需求任何类型都有 |
| `atmosphere_ref` | ✅ 必生成 | ❓ 询问确认 | 玩法类通常不需要详细氛围图 |
| `lighting_req` | ✅ 必生成 | ❓ 询问确认 | 玩法通常沿用大世界全局灯光 |
| `vfx_req` | ✅ 必生成 | ❓ 询问确认 | 取决于玩法是否有定制特效需求 |
| `audio_req` | ✅ 必生成 | ❓ 询问确认 | 取决于玩法是否有定制音频需求 |

## 玩法类询问确认规则（Phase 1.5）

当检测到玩法类关卡时，在 Phase 2 前插入 **Phase 1.5：模块选择确认**。

### 展示格式

```
【玩法类关卡 — 模块裁剪确认】
类型: {IR.type}

✅ 自动生成（6个）:
   关卡概览 · 流程图 · 情绪曲线 · 资产需求表 · 分镜 · 程序需求

❓ 需要确认（以下模块是否生成？）:
   ① 氛围参考  — 玩法类通常不需要详细氛围图，除非有特定视觉包装需求
   ② 灯光需求  — 玩法通常沿用大世界全局灯光，除非有定制化灯光方案
   ③ 特效需求  — 是否有需要专项文档化的 VFX 需求？
   ④ 音频需求  — 是否有需要专项文档化的音频设计需求？

请选择:
  A. 全部跳过（仅生成6个核心模块）  ← 推荐，快速出稿
  B. 全部生成（生成11个模块，含上述4个）
  C. 逐项确认（对每个模块单独询问）
```

### 用户选择处理

| 选择 | 处理方式 |
|------|---------|
| A（全部跳过） | `atmosphere_ref`、`lighting_req`、`vfx_req`、`audio_req` 标记为 `skipped`，写入 manifest |
| B（全部生成） | 全部 11 个模块正常生成 |
| C（逐项确认） | 对每个 ❓ 模块单独询问 yes/no |

### 例外：即使是玩法类，以下情况可强制生成被跳过的模块

- `atmosphere_ref`：若设计文档中明确提到"IP设定/视觉包装需求"
- `lighting_req`：若 IR.FEEL 有明确的灯光设计诉求（如"特殊灯光效果"）
- `vfx_req`：若 IR.ASSET 有 vfx 类型资产
- `audio_req`：若 IR.FEEL.audio_intent 字段非空

## 已跳过模块的 Manifest 记录

被跳过的模块在 manifest.json 中标记为 `skipped`，评分时不纳入结构完整性计算：

```json
"spatial_layout": {
  "status": "skipped",
  "skip_reason": "玩法类关卡，无固定场景，按规则自动跳过",
  "version": 0
}
```

## bubble_chart 模式自动选择（保持不变）

- POI / 空间类 → `spatial_bubble` 模式（情绪着色）
- OpenWorldEvent / 玩法类 → `gameplay_flow` 模式（功能类型着色）
